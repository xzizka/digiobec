## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Clerk (authenticated) → Backend | Trusted internal; Keycloak JWT validated; ROLE_CLERK required |
| Backend → PostgreSQL | Trusted; parameterized queries; audit log append-only |
| Admin Web → Keycloak | Trusted internal; PKCE flow; token stored in memory (not localStorage) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Spoofing | Stolen clerk session | mitigate | Keycloak: short access token (5min), refresh token rotation, MFA required for clerks |
| T-06-02 | Tampering | Unauthorized state change | mitigate | Server-side state machine validation; only valid transitions allowed; audit log immutable |
| T-06-03 | Repudiation | Clerk denies state change | mitigate | Audit log: submission_id, clerk_id, old_state, new_state, comment, timestamp (signed) |
| T-06-04 | Information Disclosure | CSV export contains PII | mitigate | Export only necessary fields; GDPR: clerk sees only submissions for their municipality (Phase 5 multi-tenant) |
| T-06-05 | Denial of Service | Large CSV export blocks thread | mitigate | Streaming response (WebFlux Flux<ByteBuffer>); cursor-based DB read; timeout 60s |
| T-06-06 | Elevation of Privilege | Clerk accesses other municipality data | mitigate | Phase 1: single tenant; Phase 5: RLS + municipality_id filter on all queries |
| T-06-SC | Tampering | npm/pub dependencies in admin UI | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] packages |
</threat_model>
