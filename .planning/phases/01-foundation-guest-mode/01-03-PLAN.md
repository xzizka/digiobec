## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Guest (unauthenticated) → Backend | Untrusted input; all fields validated server-side; rate limit 10 req/min/IP |
| Backend → PostgreSQL | Trusted; parameterized R2DBC queries; JSONB schema validation at write |
| Admin Web (authenticated clerk) → Backend | Trusted internal; clerk session verified via Keycloak token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | Guest impersonates another citizen | mitigate | Guest contact (email/phone) verified via OTP before submission finalized (Phase 2); for now: track IP + UA |
| T-03-02 | Tampering | Malicious form data (XSS, SQLi, oversized payload) | mitigate | JSON Schema validation (maxLength, pattern), R2DBC parameterized, request size limit 1MB |
| T-03-03 | Repudiation | Citizen denies submitting | mitigate | Audit log: submission_id, IP, user-agent, timestamp, tracking_code; immutable append-only |
| T-03-04 | Information Disclosure | Tracking code enumeration leaks submissions | mitigate | Tracking code = UUID v7 (time-ordered, unguessable); rate limit tracking code lookup |
| T-03-05 | Denial of Service | Form submission flood | mitigate | Rate limit 10/min/IP at Gateway; CAPTCHA on repeated failures (Phase 2) |
| T-03-06 | Elevation of Privilege | Guest accesses admin submission list | mitigate | Admin endpoints require ROLE_CLERK; Spring Security method-level @PreAuthorize |
| T-03-SC | Tampering | npm/pub dependencies in form validation | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] packages |
</threat_model>
